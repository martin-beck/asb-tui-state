# AR-0002: Operationalize asb-tui agent coordination

## Outcome

Make this v0.3.5 Git-backed coordinator the safe authority for future asb-tui agent work without
interrupting or retroactively claiming autonomous work that began before bootstrap.

## Scope

Repository: `martin-beck/asb-tui-state`, plus only a minimal reviewed contributor-policy pointer in
`martin-beck/asb-tui` after overlap is clear. Own coordinator validation, CI, operating guidance,
worker inventory/handoff procedure and cross-references. Do not migrate existing ASB wizard AR
authority, alter product runtime, or claim another worker's effects.

## Work sequence

1. Verify the v0.3.5 vendor manifest, immutable binding and explicit `git` backend; prove no SQLite
   database is created or consulted.
2. Add deterministic state validation for vendor integrity, task graph, generated views, privacy,
   source headers, signatures and DCO while keeping live observations separate.
3. Inventory pre-bootstrap workers and accept only durable commit/branch/PR handoffs; classify dirty
   or ambiguous effects before creating any new product worktree.
4. Add the minimal asb-tui contributor pointer only after current workers finish and path overlap is
   independently excluded.
5. Cross-reference shared ASB wizard ARs without copying, deleting or changing their authority.
6. Exercise claim, stale revision, duplicate owner/worktree, recovery and Git publication failures,
   then obtain independent exact-head review.

## Acceptance

Future asb-tui workers use this Git-backed coordinator and isolated worktrees, pre-bootstrap work is
preserved, no SQLite authority exists, and live/public state remains privacy-safe and reproducible.
