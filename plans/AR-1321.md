# AR-1321 credential-helper bridge

## Outcome

Allow a first-time or returning user to complete provider authentication from
the wizard through an approved local helper while preserving the credential-
free TUI/ASB control boundary.

## Design obligations

1. Invoke only an allowlisted provider-specific helper/keychain interface;
   never accept raw API-key text as a persisted, logged, or control-frame
   value.
2. Return only bounded public metadata: provider, locator digest, operation
   identity, and typed success/failure/cancel status.
3. Bind enrollment, rotation, revocation, and status reads to the negotiated
   runner identity and idempotency/generation fences.
4. Keep dependent model selection, configuration save, recording, and offline
   activation disabled until authoritative authenticated status is projected.
5. Add hostile privacy tests, formal wizard transitions, restart/retry tests,
   and exact TUI/ASB integration evidence.

## Acceptance evidence

- a new user can complete enrollment through the approved helper and see the
  runner status in the wizard;
- raw-key and helper-output injection tests fail closed;
- rotate/revoke/restart paths are durable and generation-bound;
- locked tests, clippy, formal-model, privacy, DCO, and hosted exact-head
  checks pass.
