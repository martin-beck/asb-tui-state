# AR-1317 implementation plan

## Outcome

Make authentication setup usable from the first-run and reconfiguration wizard
without ever sending a raw API key through TUI state, logs, arguments, or the
ASB control frame.

## Scope

Add a renderer-neutral wizard authentication handoff for provider-specific
credential enrollment, status, rotation and revocation. The UI must explain
the approved local secret-helper/keychain step, submit only endpoint and
credential-locator digests, and reflect the runner's typed result before a
provider/model selection can be saved.

## Acceptance

- A new user can select an authentication method, follow an explicit secure
  enrollment handoff, and see connected/failed/unavailable status.
- Reconfiguration can rotate or revoke the selected provider credential.
- No raw key appears in a control request, projection, persisted config,
  contextual help, terminal output, or test artifact.
- Missing authorization disables dependent models and save/recording actions;
  restart and generation changes remain fail-closed.
- Focused state/formal-model tests, privacy tests, locked clippy/tests,
  exact-head CI and post-merge verification pass.
