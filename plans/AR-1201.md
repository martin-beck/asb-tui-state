# AR-1201: Executable formal UI model and source parity

## Outcome

Make the asb-tui formal state machine an executable contract for the complete UI surface. Source,
model, ownership, routes, actions, transitions, and contextual help must remain synchronized and
CI-enforced whenever the application is extended.

## Dependencies and ownership

Product repository: `martin-beck/asb-tui`. Start from the current main and integrate the relevant
parts of PRs #70, #71, #74, #77, #81, and #87 only after exact-head review. AR-1197 supplies the
startup/wizard contract. All UI/model/renderer/application/test work stays in asb-tui; ASB owns
only backend protocol contracts.

## Work sequence

1. Inventory actual Rust UI modules, model states, routes, elements, actions, transitions, help
   entries, and owner declarations; identify omissions and duplicate authorities.
2. Define the versioned parity manifest/schema and stable ID rules, including source binding and
   visibility/reachability metadata.
3. Implement a source-aware validator and executable model binding; reject both model-only and
   source-only UI surface, unknown handlers, missing help, and schema drift.
4. Add model/property/reachability tests and TestBackend/render parity tests covering landing,
   wizard, configuration, reports/comparison, help, resize, reconnect, and failure paths.
5. Add path-filtered CI that runs the validator and tests for every affected UI/model/help change,
   with a full gate on main and privacy-safe diagnostics.
6. Re-run locked format, clippy, tests, formal checks, exact-head hosted CI, independent review,
   signatures/DCO, and record immutable evidence.

## Acceptance criteria

- Every user-facing source element/action/route has exactly one model, owner, and meaningful help
  binding; every model declaration has a source implementation binding.
- Every transition is executable, guarded, and tested for both permitted and forbidden effects;
  reachability and visibility are mechanically checked.
- A deliberate source-only, model-only, renamed-ID, missing-help, or wrong-owner fixture fails CI.
- TestBackend/render snapshots and model/property tests cover all declared routes and state changes.
- No ASB renderer, Ratatui, or application code is introduced.
