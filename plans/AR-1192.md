# AR-1192: Consume authenticated ASB agent catalog and lifecycle

## Outcome

Connect the standalone asb-tui wizard to ASB's authenticated agent catalog and verified lifecycle
without moving rendering, navigation, or application state into ASB.

## Dependencies and ownership

External dependencies: ASB AR-1190/#164, AR-1191/#165, and AR-1186/#163. Repository:
`martin-beck/asb-tui`. Owned paths: protocol client projection, executable formal UI model,
renderer/help/inventory integration, fixtures, and tests. No ASB or coordinator-state changes.

## Work sequence

1. Consume only negotiated, authenticated, generation-fenced catalog/status responses; reject
   unknown versions, replay, duplicates, malformed records, unsupported targets, and secrets.
2. Replace the free-form wizard agent field with bounded catalog search/filter/selection and
   deterministic availability reasons, focus, and contextual help.
3. Model refresh, install, progress, cancel, retry, remove, reconnect, stale generation, success,
   failure, and rollback events in the executable UI state model.
4. Keep backend effects in the authenticated control client and make state updates atomic,
   bounded, and replay-safe.
5. Add compact/plain/responsive render snapshots, model/property tests, privacy tests, and exact-head
   cross-repository fixtures after the ASB dependencies are green.

## Acceptance criteria

The wizard never invents an agent or reports installation before verified atomic activation and
self-test. Formal model, renderer, help catalog, UI inventory, and CI remain synchronized. All
operations are deterministic, bounded, and privacy-safe.

## Evidence and completion

Record exact signed heads for both repositories, focused/full gates, fixture and model evidence,
independent review, hosted exact-head CI, and post-merge verification. Qualify `asb tui install`
only after all external dependencies are complete.
