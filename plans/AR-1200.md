# AR-1200: Adopt the ASB authenticated install router

## Outcome

Make the standalone asb-tui lifecycle client consume the authenticated ASB `asb tui` control
boundary and provide the complete install/status/upgrade/remove/launch handoff without moving
the application or renderer into ASB.

## Dependencies and ownership

Dependencies: AR-1195 and ASB AR-1199, plus the verified bundle/lifecycle contracts AR-1018,
AR-1019, and AR-1020. Repository: `martin-beck/asb-tui`. Own the client transport, lifecycle
request mapping, startup/landing handoff, application state integration, docs, fixtures, and
tests. No ASB source or coordinator-state changes.

## Work sequence

1. Replace the current future-router/delegated-only boundary with an authenticated client route
   to ASB's advertised endpoint, retaining exact catalog digest/generation, release identity,
   target, operation ID, and idempotency fields.
2. Expose install, status, upgrade, remove, and launch actions in the formal UI model and wizard;
   show verification/progress/failure/retry/cancel states and return safely to landing on cancel
   or disconnect.
3. Use the document-backed contextual-help catalog and UI ownership/formal inventories for every
   new element and action. Preserve privacy-safe errors and never persist or display credentials.
4. Add deterministic protocol fixtures plus TestBackend/property, reconnect, restart, clean-home,
   stale-generation, unavailable-capability, partial-install, retry, and idempotence tests.
5. Qualify against immutable ASB revisions and a real clean-machine paired run before declaring
   the `asb tui install` journey usable.

## Acceptance criteria

The standalone application can invoke the ASB router and complete a verified install lifecycle;
all state transitions are renderer-checkable, restart-safe, and fail closed. No UI route claims
success before authenticated lifecycle confirmation. Exact-head cross-repository tests prove
wire compatibility and no ASB renderer/Ratatui/application code is introduced.

## Evidence and completion

Record immutable ASB/asb-tui heads, independent review, signatures/DCO, full hosted CI, formal
model and UI-help/ownership synchronization, clean-home evidence, and post-merge qualification.
