# AR-1202: Live terminal resize integration and qualification

## Outcome

Make terminal resize a first-class, model-checked asb-tui event that preserves user context and
renders a safe, understandable layout across all application routes.

## Dependencies and ownership

Product repository: `martin-beck/asb-tui`. Depends on AR-1201's source/model binding. Review and
integrate PR #65 only after exact-head review and rebase against current main; review related
formal/application PRs #70, #74, #77, and #87 for interactions. No ASB renderer or application
changes.

## Work sequence

1. Trace the terminal event path and current state/layout ownership; document loss or unsafe paths.
2. Specify resize event validation, storm coalescing, minimum-size fallback, focus/scroll/draft
   preservation, and terminal restoration in the formal model.
3. Implement the standalone application/renderer integration and bind every affected element and
   action through AR-1201's parity manifest and contextual help catalog.
4. Add model/property, TestBackend snapshot, and PTY tests for all routes and resize timings,
   including invalid dimensions, storms, too-small terminals, reconnect, restart, and transitions.
5. Run locked Rust/formal/CI gates and an interactive PTY qualification on supported terminals;
   document unsupported capability behavior without weakening the gate.

## Acceptance criteria

- Resize never loses route, focus, selection, scroll, drafts, or authenticated operation identity.
- Too-small and invalid terminals fail safely with meaningful contextual help and recover cleanly.
- All resize state changes are represented in and checked against the formal model and source parity.
- Deterministic automated and PTY evidence covers every route and resize timing class.
- No ASB UI/render/Ratatui/application code is introduced.
