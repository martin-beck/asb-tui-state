# AR-1197: Startup wizard readiness and idempotence

## Outcome

Provide a deterministic, fail-closed startup decision that enters the first-run wizard only after
ASB authoritatively reports absent or incomplete configuration, while configured users start on
the landing screen and can manually reopen configuration.

## Dependencies and ownership

Product repository: `martin-beck/asb-tui`. All UI/application, formal-model, renderer, and test
changes belong in that repository. Related product PRs are AR-1187/#76 (readiness classification),
PR #87 (explicit wizard decision follow-up), AR-1170/#77 (wizard state machine), AR-1182/#70
(formal model), AR-1183/#71 (ownership CI), and AR-1184/#74 (executable transitions). The ASB
repository may provide only the negotiated readiness/configuration contract.

## Work sequence

1. Independently review PR #87 at exact head
   `6d58181810774d48102eb32bb370a21b101f611f` and its dependency PR #76 at
   `1450df452f066dc14f09bef1e7b1a41ec5128032`; verify the diff has no rendering or backend code.
2. Integrate the explicit `auto_opens_wizard` decision and meaningful, privacy-safe explanations
   into the formal startup/wizard model and executable transition interpreter.
3. Bind startup to the authoritative readiness response. Preserve a landing/back path on cancel,
   require confirmed ASB commit before completion, and retain drafts without credentials.
4. Prove idempotence across restart, reconnect, resize, repeated completion, and external
   configuration changes. Unknown, stale, malformed, unavailable, and unauthorized states must
   never auto-open or claim configured status.
5. Add model/property tests and renderer parity/TestBackend snapshots for every readiness and
   wizard path. Extend UI ownership and CI synchronization checks for all new elements.
6. Run focused and full locked Rust gates, exact-head hosted CI, privacy/signature/DCO review, and
   record immutable evidence before promotion or merge.

## Acceptance criteria

- Explicit unconfigured/incomplete readiness auto-opens the wizard once with an actionable reason.
- Valid configured readiness opens landing and exposes manual Configure/Reconfigure navigation.
- Unsafe or unknown readiness remains recoverable and neither opens the wizard nor claims configured.
- Wizard cancel preserves a safe route and draft; completion returns only after authoritative commit.
- Restart, reconnect, resize, repeated completion, and external changes produce deterministic,
  idempotent decisions.
- Formal model, executable transitions, renderer parity, UI ownership, and CI checks stay in sync.
- No ASB Ratatui/render/application code is introduced; all actual TUI behavior remains standalone.
- Exact-head tests, hosted CI, SSH signatures, DCO, independent review, and privacy gates pass.
