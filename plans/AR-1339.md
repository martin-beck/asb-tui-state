# AR-1339 — Top-level ASB TUI install and launch integration

## Scope

Expose the standalone application through the supported top-level ASB command
contract. Implement `asb tui install` to select, verify, and install a
qualified asb-tui bundle, and `asb tui` to launch the installed TUI. Provide
status, upgrade, remove, and recovery behavior needed by the install flow.
The development channel must support local signed fixtures without requiring
live provider authorization, while production bundles remain fail-closed.

## Dependencies

Depends on AR-1200, AR-1324, AR-1327, and the existing lifecycle/bundle
contracts in asb-tui.

## Acceptance

- `asb tui install` is a supported, documented top-level command that accepts
  only a bounded typed request, verifies the exact bundle manifest/signature,
  installs privately and atomically, and reports one actionable recovery on
  failure.
- `asb tui` launches the exact installed bundle through the controlled
  supervisor path, preserves terminal state, and never executes an unverified,
  mutable, or substituted candidate.
- `asb tui status`, `upgrade`, and `remove` are truthful and scoped to the
  exact installation identity; interrupted install/upgrade rolls back safely.
- Development fixture mode is explicit and warning-labelled; it may operate
  without live authentication, provider access, or an authenticated router.
  Production/public promotion remains gated by signed release evidence.
- Tests exercise fresh install, idempotent reinstall, upgrade, rollback,
  launch/quit, missing bundle, bad signature, tampering, and unrelated-process
  isolation. The standalone binary and the top-level router have matching
  command/status schemas.
