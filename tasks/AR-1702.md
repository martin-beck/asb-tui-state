Recording and replay are development workflow features. Generated signatures
and keys are acceptable and missing production key management never blocks the
journey. The UI must state which responses were recorded, prevent accidental
network access during strict replay, and make comparison/analysis available
without requiring users to copy paths or edit files.

The record/replay/comparison acceptance must start from the supported installed
entrypoint (`asb tui install`, then `asb tui`) and prove that the installed
handoff preserves the selected workloads and live/offline mode across restart;
an internal binary-only test does not satisfy this AR.
